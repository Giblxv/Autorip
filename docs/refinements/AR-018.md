# AR-018 — Cliente Android e acesso LAN opt-in

## Achado

O repositório fornecia apenas o painel web local e o servidor escutava exclusivamente em `127.0.0.1`, portanto um telefone não conseguia operar o painel. A pasta de compilação do Drive continha fontes e instaladores Windows/Linux, mas não continha um projeto Android/Capacitor utilizável.

## Mudança

Foi criado `mobile/`, um cliente Android Capacitor que abre o painel existente após o operador informar o endpoint. O cliente guarda somente até cinco endpoints recentes no armazenamento local; não guarda senha nem tenta alterar PRT, canais, branco, ICC, meio-tom, mirror ou geometria.

O servidor recebeu `AUTORIP_BIND_HOST`, `AUTORIP_ALLOWED_HOSTS` e `AUTORIP_PUBLIC_HOST`. O padrão permanece loopback. A abertura para LAN exige configuração explícita e uma lista de hosts permitidos; a autenticação por senha/token permanece intacta. Foi incluído workflow separado `mobile-apk.yml`, acionado manualmente ou por tags `mobile-v*`, para publicar uma release prévia móvel sem substituir releases Windows.

- SHA-256 local: `022d65b8ad4e288b3fd70b89083859ec7eee0cb4a4b49f7f1d73e7a704831f41`.

## Riscos e bloqueios

O APK é um cliente do servidor, não um RIP autônomo; o computador/servidor precisa continuar ligado e acessível. HTTP em LAN só deve ser usado em rede privada controlada; para internet, usar HTTPS/VPN. O build local ARM64 exigiu Capacitor 6/API 34 por limitações do AAPT2 disponível; o workflow oficial usa runner Ubuntu e deve ser validado no GitHub antes de distribuir uma versão de produção. O APK gerado é debug e não é assinado para publicação em loja.
