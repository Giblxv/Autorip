# AR-017 — Redirecionamentos do atualizador

## Achado

O atualizador validava o host de cada redirecionamento, mas aceitava qualquer caminho no `github.com`. Um redirecionamento para outro caminho do GitHub poderia escapar da expectativa de baixar exclusivamente um asset de release, ainda que o primeiro URL da API fosse validado.

## Mudança

O handler de redirecionamento agora aceita CDNs já permitidas e, quando o destino permanece em `github.com`, exige o prefixo `/Giblxv/Autorip/releases/download/`, HTTPS, porta padrão e ausência de query/fragmento. O download inicial continua validando o nome exato do asset e o caminho exato na API. Nenhuma lógica de PRT ou processamento de arte foi alterada.

## Evidência

- Teste focado do atualizador: **43 passed em 0,25 s**.
- `python -m compileall -q autorip tools`: passou.
- `git diff --check`: passou.
- Testes adicionados cobrem CDN permitida, caminho de release válido, arquivo do repositório, página de release e query inesperada.

## Riscos e bloqueios

A proteção depende da allowlist de hosts já existente e não substitui a conferência SHA-256 do instalador. A mudança não foi exercitada contra um servidor real de redirecionamento neste ambiente; o comportamento do handler foi coberto por testes de URL. Nenhuma release foi publicada ou modificada.
